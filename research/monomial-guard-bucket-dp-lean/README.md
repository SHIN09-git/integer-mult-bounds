# 压缩动态规划从原始行到最短行加法序列

输入是域 $K$ 上的 $m$ 行原始数据。第 $i$ 行有标量 $u_i,b_i$ 和 $d$ 维向量 $w_i$，电荷为 $y_i=u_i w_i$。可执行入口 `BucketDP.solve` 只接收这三个数组，计算 $\tau=\sum_i y_i$，按总电荷选择目标，并返回真实标签分组和带系数的行加法序列。Lean 证明每条指令合法、执行后达到目标，且所有允许免费换位、非零缩放及使用零电荷行的合法方案都至少要付出同样多的行加法。[总入口与定理](BucketDP/EndToEnd.lean) · [两类目标](BucketDP/Solver.lean)

## 已证明的总费用

令 $h$ 为非零真实行数。分离情形 $\tau=0$ 使用 $H=h$ 个标签，最短长度为 $\ell=h-Z$。集中情形 $\tau\ne0$ 添加一个电荷为 $-\tau$ 的虚拟标签，使用 $H=h+1$ 个标签，最短长度为 $\ell=h-Z_*$。在各自的输入上统计实际出现的 $t$ 种电荷及重数 $n_j$，令 $N=\prod_{j=1}^{t}(n_j+1)$。真实行和虚拟项电荷相同时共用一个桶，该类型的重数增加一。空输入取空乘积 $N=1$。[实际表尺寸](BucketDP/EndToEnd.lean) · [分组投影](BucketDP/Project.lean)

在下述字长 RAM 模型内，两种情形及自动选择目标的入口都满足

$$
T=O\!\left((m+1)(1+d)+(1+t+d)N+\ell\right),\qquad
S=O\!\left((m+1)(1+d)+(1+d)N+\ell\right).
$$

这里 $S$ 是包含原始输入、工作区和返回结果的空间上界。Lean 对两个括号分别给出统一常数 384 和 192，并用 mathlib 的大 $O$ 关系证明维数、行数和类型数可同时变化。零电荷行也要读取，故第一项使用物理行数 $m$。显式列出 $\ell$ 可以看出写出系数和保存操作序列的代价。[读取原始行与系数输出计费](BucketDP/InputCost.lean) · [逐阶段费用](BucketDP/Costs.lean) · [各阶段数据与实际程序的关系](BucketDP/Accounting.lean)

| 阶段 | 如何计费 |
|---|---|
| 求总和、过滤零电荷 | 对所有 $m$ 行逐坐标求电荷并累加到立即生成的向量。第二遍生成每个非零行的标签及缓存。计入坐标索引、零检验、向量构造和虚拟电荷取负。 |
| 识别类型、建桶 | 确定性地扫描已知类型，实际类型比较最多 $Ht$ 次；随后每种类型扫一遍输入，恰好做 $tH$ 次比较。每次至多比较 $d$ 个坐标，首个不同坐标即退出。桶中列表节点总数恰为 $H$。 |
| 填表 | 沿用步长版本的实际填表计数。计入数组中的 $N$ 个单元、父地址及稠密累加缓存。完成时表占用的计费字数恰好是 $3+(10+3d)N$。 |
| 回溯、移除虚拟项 | 当前地址减父地址得到步长。长为 $N+1$ 的数组直接索引相应桶的表头。沿完整路径恰好弹出 $H$ 个身份，按切分标记组成各组。投影逐项保留 `some i`，剔除唯一的 `none`。 |
| 生成指令 | 以组首 $j$ 为枢轴，对其余每个 $i$ 直接从原始数组读取 $u_i,u_j$，写出行号和系数 $-u_i/u_j$。恰好做 $\ell$ 次除法和 $\ell$ 次取负。指令解释器用于证明和样例回放，生成器直接输出系数。 |

每个已观察类型的重数为正，因此 Lean 证明了 $2+(1+t)H\le 2N$。这一步把基于比较的识别和建桶费用吸收到 $O((1+d)N)$，不需要假设随机哈希。桶回溯的输出逐标签满足计数等式，每个原本非零的真实标签出现一次，每个原本为零的真实标签出现零次。集中情形的带标记路径中恰有一个虚拟标签；投影后每个真实标签的计数保持不变。[乘积不等式](BucketDP/Size.lean) · [比较次数](BucketDP/Visits.lean) · [取桶证明](BucketDP/Queues.lean) · [系数与终态](BucketDP/Emit.lean)

## 资源模型

一个行号、地址、指针、计数器或域元素各占一个字。地址和计数须适合模型字长。随机读写、机器字算术、域上的加法、乘法、取负、相等判断和除法按常数费用计；一个原始坐标由数组随机读取。数组预留容量，由单一写者更新。输入数组、目标向量、类型目录、桶头和标签节点、递归工作栈、整张表、回溯路径、分组及输出指令均纳入空间预算。不同阶段的临时使用量取最大值，同时存活的区域相加。[RAM 费用定义](BucketDP/Costs.lean) · [稠密填表模型](../monomial-guard-stride-dp-lean/StrideDP/Dense.lean)

账本依据实际循环和缓冲区的尺寸计算。逐坐标比较记录提前退出，填表引用已有执行计数。各阶段按明确的常数预算计入索引、列表节点和局部工作；验证用的观察函数可以重新遍历数据，求解入口不调用该观察函数。位复杂度、Lean 运行时的垃圾回收和操作系统报告的峰值内存属于不同的度量。
