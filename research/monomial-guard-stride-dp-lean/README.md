# 压缩动态规划的前驱、最优操作与填表复杂度

给定按顺序排列的互异电荷类型、各类型的重数上限 $n_j$ 和电荷维数 $d$，程序按地址递增填完 $N=\prod_{j=0}^{t-1}(n_j+1)$ 个状态。Lean 证明了每格的得分、获胜类型和切分标记与原计数动态规划相同。沿父地址回溯可以恢复零目标和非零目标的最短真实行操作序列。[逐格证明](StrideDP/Correctness.lean) · [操作序列](StrideDP/Witness.lean)

## 混合进位地址

设 $s_0=1$，$s_j=\prod_{u<j}(n_u+1)$。状态 $c$ 的地址为 $k=\sum_j c_js_j$。第 $j$ 个计数为正时，删去一个该类型电荷的前驱地址为 $k-s_j<k$。每个 $0\le k<N$ 都解码成一个合法状态，重新编码后仍为 $k$。重数上限为零的轴也适用。[地址与双向对应](StrideDP/Grid.lean) · [原编码](../monomial-guard-count-dp-lean/CountDP/Address.lean)

固定第 $j$ 轴时，可作前驱的本轴正计数有 $n_j$ 种，其余轴各有 $n_u+1$ 种取值。填完整张表的实际前驱读取次数恰为

$$
E=\sum_{j=0}^{t-1} n_j\prod_{u\ne j}(n_u+1)\le tN.
$$

证明先对物理地址上的非零位数求和，再证明程序每遇到一个正计数恰读一次数组。若两个前驱的分数相同，程序保留在类型列表中靠前的一个。[组合计数](StrideDP/Edges.lean) · [选择前驱](StrideDP/Scan.lean) · [实际读数](StrideDP/Cost.lean)

## 填表和回溯

每个轴保存类型引用、进位基数和步长。扫描用商和余数取出计数位，用 $k-s_j$ 读取前驱。候选之间只比较分数并保留获胜行的引用。选定前驱后，程序才将其缓存电荷加上当前类型，并检查总和是否为零。空状态得零分，每个非空的零和状态在前驱得分上增加一分。[填表实现](StrideDP/Machine.lean)

每行记录得分、父类型、父地址、切分标记和缓存电荷。回溯从目标地址沿父地址前进，用切分标记恢复类型分组，再分配回真实标签。总电荷为零时生成恰好 $h-Z$ 次真实行加法。总电荷为非零目标 $\tau$ 时，增广分组中的虚拟标签按身份移除，生成恰好 $h-Z_*$ 次真实行加法。两条最优性定理都覆盖操作合法性、执行后的电荷和全局下界。[回溯、分组与操作](StrideDP/Witness.lean) · [操作模型](../monomial-guard-dp-lean/GuardDP/Solver.lean)

## 计费模型

填表入口接收准备好的轴表和 $N$。地址、计数、分数和引用按机器字存取。字长足以容纳索引及计数，取商、取余、数组访问、预留容量内的追加及单个域元素的运算按单位费用计算。输入电荷支持按坐标常数时间读取。稠密实现把每个缓存向量实际存成长度 $d$ 的标量列表，逐坐标加法和判零都在代码中计费。[稠密表示与费用证明](StrideDP/Dense.lean)

扫描一个状态的控制费用恰为 $1+6t+10r$，其中 $r$ 是该行的合法前驱数。这是程序采用的费用表，每个分支分配固定的控制操作预算。全表还计入预留数组、生成零向量、追加各行及获胜向量的处理费用。表空间按数组头、每行的引用和元数据、缓存向量占用的字数计算。Lean 给出了对任意输入统一成立的界

$$
T_{\mathrm{fill}}\le48(1+t+d)N,\qquad
M_{\mathrm{table}}\le16(1+d)N .
$$

填表时间为 $O((1+t+d)N)$，结果表空间为 $O((1+d)N)$。这两个 mathlib 定理允许 $t,d,N$ 随同一输入族变化。空字母表和 $d=0$ 都在证明范围内。时间界从已给定的轴表开始，到数组填满为止。由原始标签建立直方图、输出阶段的分组回溯和行加法生成另行计费。空间界度量结果表的机器字数，运行时分配器、调用栈和输出序列属于其他空间项目。[显式上界](StrideDP/Cost.lean) · [大 O 定理](StrideDP/Asymptotics.lean)

## 复现

检出同一提交下相邻的三个目录，即本包、计数动态规划包和标签动态规划包。安装项目固定的 Lean 4.24.0 后，在本目录运行

~~~powershell
./prepare.ps1
lake build StrideProofCheck
lake env lean Examples.lean
~~~

完整验证使用与该 Lean 版本匹配的官方 lean4checker。将其放入命令搜索路径后运行下列脚本，也可用参数指定 Lean 和检查器的位置。

~~~powershell
./verify.ps1
~~~

脚本核对两个前序证明包的收据和 55 个输入文件、固定的 Git 依赖、编译结果、8 组可执行检查及 35 条声明的传递公理。随后以空环境重放 StrideProofCheck 的导入链，并再次核对输入文件。复现时日志写入本地的 .verification-runs 目录。[本次验证收据](verification/RESULT.json) · [公理清单](verification/axioms.log) · [依赖记录](verification/dependencies.json) · [内核记录](verification/kernel-replay.log)
